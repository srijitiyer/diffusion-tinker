# Mechanistic causes of instability / seed variance when applying policy-gradient RL to guidance-distilled and timestep-distilled diffusion/flow models

Scope note for the report writer: every claim below is tagged **[MEASURED]** (reported empirical result), **[THEORY]** (derived analytically, not measured), or **[UNSUPPORTED MECHANISM]** (plausible chain of reasoning I constructed from the cited pieces, with no single source asserting it). Several of the arXiv IDs returned by search are 2026 preprints; where a result came only from a search-engine summary rather than from text I fetched myself, I say so explicitly.

---

## Q1. How exactly is FLUX.1-dev guidance-distilled, and what does that do to its output distribution?

### Takeaway
FLUX.1-dev replaces true classifier-free guidance with a scalar `guidance` value injected as a conditioning embedding alongside the timestep embedding, so one forward pass emits an already-guided velocity field. This is confirmed by Black Forest Labs' model card, the diffusers implementation, and multiple RL papers that describe FLUX.1-dev as "a guidance-distilled model that operates without explicit CFG". The consequence for the output distribution — that the model reproduces a *tilted*, lower-entropy, CFG-sharpened distribution rather than the true conditional — is asserted in the distillation literature and visible in the fact that no unconditional branch exists, but I found no paper that directly measures FLUX.1-dev's output entropy against a de-distilled reference.

### Cited Findings
- The official model card states FLUX.1-dev was "Trained using guidance distillation, making `FLUX.1 [dev]` more efficient" and is "second only to our state-of-the-art model `FLUX.1 [pro]`"; it gives no further mechanical detail and does **not** formally describe itself as a distillation of [pro] — [Black Forest Labs, FLUX.1-dev model card](https://huggingface.co/black-forest-labs/FLUX.1-dev)
- BFL's own discussion thread on the model repo describes the mechanism concretely: the model "was trained to replicate the output of the base model with classifier-free-guidance in a single forward pass (instead of two passes for CFG), with the guidance scale passed as a parameter to the model" — [FLUX.1-dev discussion #17, "What is guidance-distilled?"](https://huggingface.co/black-forest-labs/FLUX.1-dev/discussions/17) (note: this is a repo discussion, authoritative-adjacent rather than a formal technical report; BFL has published no FLUX.1 technical report describing the distillation objective)
- Diffusers docs: `guidance_scale` defaults to 3.5 and "enables embedded guidance when set greater than 1"; Flux-dev "does not use negative prompts for classifier-free guidance (CFG) because this guidance is already distilled into the model" — [diffusers Flux pipeline docs](https://huggingface.co/docs/diffusers/api/pipelines/flux)
- Implementation, `FluxTransformer2DModel`: a config flag `guidance_embeds` selects the embedding class — `text_time_guidance_cls = CombinedTimestepGuidanceTextProjEmbeddings if guidance_embeds else CombinedTimestepTextProjEmbeddings`. In `forward`, guidance is scaled identically to the timestep (`timestep = timestep.to(hidden_states.dtype) * 1000`; `guidance = guidance.to(hidden_states.dtype) * 1000`) and then `temb = self.time_text_embed(timestep, guidance, pooled_projections)`. So guidance enters as part of the *same additive conditioning vector as time*, feeding every transformer block's modulation — [diffusers `transformer_flux.py`](https://raw.githubusercontent.com/huggingface/diffusers/main/src/diffusers/models/transformers/transformer_flux.py). *Version-pinned: I verified this code is identical in the locally installed **diffusers 0.37.1** (`text_time_guidance_cls` selection at L600-601, `guidance * 1000` at L684, `time_text_embed(timestep, guidance, pooled_projections)` at L689), so the citation applies to the environment actually in use, not only to GitHub `main`.*
- RL papers treat this as a defining property: V-GRPO uses "FLUX.1-dev, a guidance-distilled model that operates without explicit Classifier-Free Guidance (CFG)" — [V-GRPO, arXiv 2604.23380](https://arxiv.org/pdf/2604.23380) (text extracted from the PDF)
- The canonical formulation of this kind of distillation (one network taking `w` as input and matching the `w`-guided output) is "On Distillation of Guided Diffusion Models", which introduces the guidance-scale-conditioned student explicitly, noting original CFG evaluates the network twice while the distilled student needs one evaluation — [Meng et al., CVPR 2023](https://openaccess.thecvf.com/content/CVPR2023/papers/Meng_On_Distillation_of_Guided_Diffusion_Models_CVPR_2023_paper.pdf)
- Community-reported practical consequence: training on FLUX.1-dev is normally done with `guidance_scale = 1.0`, which differs from the inference default of 3.5; de-distillation projects exist precisely to restore a CFG-capable model (prompt dropout plus decaying the projected guidance embedding over training) — [HF forum: Guidance Scale for Flux LoRA](https://discuss.huggingface.co/t/guidance-scale-for-flux-lora/140288); [nyanko7/flux-dev-de-distill](https://huggingface.co/nyanko7/flux-dev-de-distill/discussions/3); [Erwann Millon on de-distillation](https://x.com/ErwannMillon/status/1822822006917845393)

### Inferences
- **[UNSUPPORTED MECHANISM]** Because guidance is injected into the *same* additive embedding as the timestep and modulates every block, the model's velocity field is a single learned function `v_θ(x, t, w, c)` whose target is the CFG-combined velocity `v_cond + w(v_cond − v_uncond)`. The sampler's marginals therefore track the *guidance-tilted* distribution `∝ p(x|c)·(p(c|x))^(w−1)`, not `p(x|c)`. Any SDE constructed to "preserve the model's marginals" (Flow-GRPO's Eq. 7/8) is therefore preserving a tilted distribution — which is self-consistent for RL purposes, but means the model was never trained to represent a true score at any `w`, so `∇ log p_t` substitutions inside the ODE→SDE conversion are only approximate. I found no paper stating this directly for FLUX.1-dev.
- **[UNSUPPORTED MECHANISM]** `w` being a conditioning input means the *same weights* must serve all guidance scales. LoRA/full fine-tuning that moves the weights at `w=1` (the common training convention) changes behaviour at the `w=3.5` inference setting in an uncontrolled way — a train/inference mismatch distinct from the SDE/ODE mismatch.

### Gaps
- No BFL technical report or paper giving the FLUX.1-dev distillation loss, the `w` range it was trained over, or the teacher used. The repo discussion is the most authoritative description found.
- No measurement of how `v_θ(·, w)` deviates from true CFG at `w=3.5` for FLUX specifically.

## Q2. Does guidance distillation reduce output entropy / sample diversity? Is there measured evidence? (and the GRPO advantage-collapse link)

### Takeaway
Two separate, well-established findings combine here: (a) CFG itself reduces diversity monotonically in guidance strength, and CFG-distilled students additionally lose diversity relative to their CFG-free initialization; (b) GRPO's advantage `(r − mean)/std` collapses to zero when within-group reward variance vanishes. Both halves are published and (a) is at least qualitatively measured; the *conjunction* — that FLUX.1-dev's distillation-reduced diversity is what starves GRPO of advantage signal — I did not find asserted in any source.

### Cited Findings
- "Diversity-Rewarded CFG Distillation" states CFG "doubles inference cost while limiting originality and diversity across generated contents", and that the CFG-distilled model "suffers from a decrease in diversity compared to its initialization, the CFG-free base model". Their validation is human evaluation on MusicLM (quality-diversity preference), and the diversity reward used is negative cosine similarity between samples — [arXiv 2410.06084](https://arxiv.org/abs/2410.06084). **Important caveat: when I fetched the paper page I could not find quantitative diversity numbers for the distilled-vs-base comparison — the evidence presented is a human-eval quality-diversity judgement, not a reported diversity metric with error bars. Treat "CFG distillation reduces diversity" as measured-qualitatively, not quantified.**
- Mechanism for the CFG half: "CFG reduces the diversity of generated outputs as the guidance factor increases, because stronger guidance encourages the model to adhere closely to the prompt, leading to outputs that are more similar to each other" — from the search synthesis over [2410.06084 / related](https://www.emergentmind.com/papers/2410.06084) (search-engine summary; I did not verify this exact sentence in a primary PDF)
- Direct observation about FLUX.1-dev's narrow output distribution: it "produces nearly redundant outputs for the prompt 'a portrait photo of a woman', capturing only a narrow subset of the potential distribution" — [Don't Settle at the Mode! Mitigating Diversity Collapse in Pretrained Flow Models via Feature Self-Guidance, arXiv 2606.27371](https://arxiv.org/pdf/2606.27371) (from search summary; this is the single most on-point citation for FLUX-specific low diversity, and it attributes the collapse to the *pretrained* flow model, not specifically to guidance distillation)
- Step-distilled models lose diversity too: "Adversarial, consistency, and score-distillation schedulers collapse multi-step denoising into one forward pass but reduce per-prompt sample diversity" — [arXiv 2606.27371 context](https://arxiv.org/pdf/2606.27371) (search summary)
- DMD+RL work reports the quality/diversity trade-off concretely: their method "reduces sample diversity compared to baselines (Table 6: LPIPS scores lower than teacher)" — [Distribution Matching Distillation Meets Reinforcement Learning, arXiv 2511.13649v2](https://arxiv.org/html/2511.13649v2)
- GRPO advantage collapse is a named, analyzed failure mode: "GRPO is prone to advantage collapse, a failure mode where homogeneous rewards within a group (e.g., all correct or all incorrect answers) yield near-zero advantages and vanishing gradients"; "when within-group reward variance vanishes" the "outcome-driven gradient signal collapses" — [Advantage Collapse in Group Relative Policy Optimization: Diagnosis and Mitigation, arXiv 2605.21125](https://arxiv.org/html/2605.21125v1)
- Mode collapse is being addressed directly in image-generation GRPO — [DiverseGRPO: Mitigating Mode Collapse in Image Generation via Diversity-Aware GRPO, arXiv 2512.21514](https://arxiv.org/pdf/2512.21514)
- Flow-GRPO measures the *reverse* direction (RL causing collapse): removing KL regularization on the PickScore task "causes a collapse in visual diversity. Outputs converge to a single style, **with different seeds producing nearly identical results**" — [Flow-GRPO, arXiv 2505.05470](https://arxiv.org/pdf/2505.05470), §5.3 (extracted from PDF text)
- Flow-GRPO also shows that exploration noise, not policy entropy, is the lever they pull: noise level `a = 0.1` "limits exploration and slows reward improvement", `a` up to 0.7 "boosts exploration and speeds up reward gains", beyond 0.7 no further benefit, and too much noise "degrades image quality, resulting in zero reward and failed training" — [Flow-GRPO §5.3](https://arxiv.org/pdf/2505.05470)
- Group size matters for advantage quality: "smaller group sizes produce inaccurate advantage estimates, increasing variance and leading to" degraded training; Flow-GRPO uses `G = 24` — [Flow-GRPO §5.3 and Appendix](https://arxiv.org/pdf/2505.05470)

### Inferences
- **[UNSUPPORTED MECHANISM — this is the central conjecture of the brief and it is NOT published]** Guidance distillation lowers per-prompt output entropy; GRPO's advantage is `(r − mean)/std` over a group of `G` samples from one prompt; therefore a lower-entropy policy produces smaller within-group reward spread, so the advantage numerator shrinks while the denominator `std` also shrinks, making the normalized advantage a ratio of two small, noisy quantities. The *normalization* means the signal does not vanish outright — it becomes dominated by whichever few samples happen to deviate, which is a high-variance, seed-sensitive estimator. No source states this for guidance-distilled image models; the advantage-collapse literature is LLM-side with binary rewards, where the failure is literal zero (all-correct/all-wrong), and continuous image rewards do not produce exact ties.
- **[UNSUPPORTED MECHANISM]** Flow-GRPO's exploration is injected by the SDE noise `σ_t`, which is *independent of the policy's own entropy*. This partially insulates the method from a low-entropy base model — exploration comes from the sampler, not the policy. That argues against the naive "distilled model can't explore" story for Flow-GRPO-style SDE methods, and shifts the burden onto log-prob conditioning (Q3).

### Gaps
- No measurement of FLUX.1-dev output diversity (e.g. pairwise LPIPS / DINO dispersion per prompt) versus a de-distilled or CFG-run equivalent. This is the single most important missing number for the brief's thesis.
- No paper reports within-group reward std for FLUX.1-dev vs SD3.5-M under identical GRPO setups.

## Q3. Is the SDE transition log-probability miscalibrated / ill-conditioned / high-variance for distilled or few-step models? The σ→0 limit.

### Takeaway
Yes — this is now a well-developed, *published and measured* line of work, and it is the strongest-supported part of the brief. The Gaussian transition log-probability in flow-GRPO carries an exact, analytically derivable `1/σ_t²` factor that makes the importance ratio systematically biased below 1 and makes its variance and gradient magnitude scale wildly across timesteps — measured at roughly 20× gradient-magnitude variation across timesteps, with low-noise (small σ) steps dominating. Separately, FLUX.1-dev specifically is reported to need variance-reduction machinery that SD3.5-M does not.

### Cited Findings
- Flow-GRPO's construction: the reverse SDE preserving marginals is `dx_t = [v_t(x_t) − (σ_t²/2)∇log p_t(x_t)]dt + σ_t dw`; for rectified flow it becomes `dx_t = [v_t + (σ_t²/2t)(x_t + (1−t)v_t)]dt + σ_t dw`; Euler-Maruyama gives an isotropic Gaussian policy `π_θ(x_{t−1}|x_t,c)` with `σ_t = a·sqrt(t/(1−t))`. The closed-form KL is `‖x_{t+Δt,θ} − x_{t+Δt,ref}‖²/(2σ_t²Δt)` — [Flow-GRPO §4, Eq. 6–9](https://arxiv.org/pdf/2505.05470). Note `σ_t = a·sqrt(t/(1−t)) → 0` as `t → 0`, so the `1/σ_t²` factor in the log-prob and KL **diverges at the clean-image end of the trajectory**.
- **[THEORY, then MEASURED]** GRPO-Guard derives the bias exactly: `E[log r_t(θ)] = −‖Δμ_θ‖²/(2σ_t²Δt)`, "which explains the negative bias independent of model updates". Empirically "the importance-ratio distribution exhibits a systematic bias: its mean consistently falls below 1" and its variance "varies significantly across timesteps", with "leftward mean shift and increasing variance at low-noise timesteps" (their Fig. 2b) — [GRPO-Guard, arXiv 2510.22319](https://arxiv.org/html/2510.22319v1)
- **[MEASURED]** GRPO-Guard: "Gradient magnitudes vary ~20× across timesteps (Figure 3), with low-noise steps dominating." Consequence for clipping: at high-noise steps σ_t is large so "clipping rarely triggers; positive-advantage samples pass unchecked", while at low-noise steps σ_t is small so "clipping occurs excessively" — [GRPO-Guard](https://arxiv.org/html/2510.22319v1)
- GRPO-Guard's root-cause framing: "diffusion models compute Gaussian probabilities, whereas LLMs rely on discrete token probabilities, yet FlowGRPO … directly inherits the GRPO formulation without proper adaptation." Their fix is a normalized ratio `log r̂_t(θ) = σ_t√dt[log r_t(θ) + ‖Δμ_θ‖²/(2σ_t²dt)] = −Δμ_θ·ε` plus gradient reweighting `δ = 1/dt` (Flow-GRPO) or `δ = β/dt` (DanceGRPO) — [GRPO-Guard](https://arxiv.org/html/2510.22319v1)
- GRPO-Guard tests on **both SD3.5-M and FLUX.1-dev**, and on GenEval reports normalized gold score 1.02 (GRPO-Guard) vs 0.88 (DanceGRPO baseline); baseline DanceGRPO on FLUX showed "distinct horizontal and vertical stripe artifacts" from severe reward hacking. They offer **no special discussion of guidance distillation** — [GRPO-Guard](https://arxiv.org/html/2510.22319v1)
- λ-Controlled GRPO unifies these symptoms: "Training in this setting is unstable in a way specific to multi-step denoising: the policy update changes systematically across denoising steps, with importance ratios drifting below one, becoming increasingly dispersed, clipping at different rates, and leaving fewer usable samples late in training… they arise from a single per-step quantity, which we call path variance. This quantity is determined exactly by the sampler's Gaussian transition kernel and can be estimated cheaply during training." They "allocate gradient effort across denoising steps according to their predicted cost" and report improvements on OCR text rendering and a preference reward — [λ-Controlled GRPO, arXiv 2609.22041](https://arxiv.org/abs/2609.22041)
- **[MEASURED, FLUX-specific]** V-GRPO (ELBO-surrogate GRPO) diagnoses instability on FLUX.1-dev: "the magnitude of the per-sample loss ℓ_θ(t_j, ε_j) varies substantially across timesteps t_j", sampling `(t_j, ε_j)` independently per output "yields high-variance surrogates that could fail to faithfully reflect the relative likelihoods", and "gradient norms scale with surrogate magnitude… Unstable pretraining losses thus propagate into high-variance gradients, where noise in the surrogate magnitudes overwhelms the reward signal and destabilizes training." Statistics computed over ~20K samples using FLUX.1-dev — [V-GRPO, arXiv 2604.23380](https://arxiv.org/pdf/2604.23380)
- **[MEASURED]** V-GRPO's variance numbers: their three fixes drop the coefficient of variation of surrogate magnitude from 0.230 → 0.128, "driven primarily by a lower mean within-group CV (0.170 → 0.038)", and reduce the R² of a quadratic fit of gradient norm on surrogate magnitude from 0.406 → 0.328 — [V-GRPO](https://arxiv.org/pdf/2604.23380)
- **[MEASURED, directly relevant to FLUX-vs-SD3.5 difficulty]** V-GRPO: "Without these methods, the naive baseline suffers from severe training instability" on FLUX.1-dev; removing group-shared timestep-noise pairs *or* stratified timestep sampling "similarly destabilizes training". By contrast, for SD3.5-M "ablating individual components has a limited effect on both stability and performance. This indicates that **SD 3.5 M is inherently more robust to ELBO-based training**" — [V-GRPO §5.4](https://arxiv.org/pdf/2604.23380). This is the closest published statement that FLUX.1-dev is *harder* to RL than SD3.5-M.
- V-GRPO also reports KL penalty alone is insufficient: "the KL penalty alone is insufficient to stabilize training of FLUX.1-dev", and that advantage soft-clipping was needed specifically when they reduced FLUX.1-dev sampling steps from 25 to 16 — [V-GRPO §5.4, Fig. 4b/4d](https://arxiv.org/pdf/2604.23380)
- V-GRPO's numerical-precision practice is itself evidence of conditioning problems: "we employ BF16 mixed precision during rollout, while retaining full FP32 precision for master weights, ELBO-based surrogate computation for both π_θold and π_θ, and the backward pass" — [V-GRPO §5.1](https://arxiv.org/pdf/2604.23380)
- **Guidance-embedding-specific likelihood claim (needs verification):** a search synthesis reported that "Flow-GRPO fails on FLUX.2 because its likelihood estimation becomes inaccurate when the CFG guidance scale is embedded in the Diffusion Transformer. However, NFT outperforms GRPO on FLUX.1." I could **not** locate this sentence in a primary PDF — it appeared only in the search-engine summary for the query about FLUX.1-dev guidance-distilled RL difficulty. **Flag as unverified; if the report writer wants this claim, it must be re-sourced.** Candidate sources to check: [DiffusionNFT / arXiv 2509.16117 line of work], [V-GRPO 2604.23380](https://arxiv.org/pdf/2604.23380).
- Train/inference sampler mismatch has its own theory paper: training with SDE and inferring with ODE creates a characterized "reward gap", with "non-vacuous bounds for general diffusion models, along with sharper convergence rates for Variance Exploding (VE) and Variance Preserving (VP) Gaussian models"; empirically "reward gaps consistently narrow over training, and ODE sampling quality improves when models are updated using higher-stochasticity SDE training" — [Understanding Sampler Stochasticity in Training Diffusion Models for RLHF, arXiv 2510.10767](https://arxiv.org/pdf/2510.10767)
- Discretization itself is implicated: "Finite-step SDE discretization is identified as a central source of the training–inference gap in flow-based GRPO, with adverse effects on rollout quality and reward alignment" — [LC-GRPO, arXiv 2608.05600v1](https://arxiv.org/html/2608.05600v1) (search summary of abstract)
- Spatial aggregation loses information: "Flow-GRPO aggregates the likelihood over all latent dimensions into a single transition-level policy signal, discarding spatial decomposition, which means all spatial tokens receive the same advantage despite contributing differently to the final reward" — [SGA-Flow-GRPO, arXiv 2609.32340v1](https://arxiv.org/html/2609.32340v1) (search summary)
- Original DDPO already needed all-timestep log-probs: it "requir[es] estimation of log-probabilities for samples at all diffusion steps, which are then summed over and weighted by the final reward"; the score-function estimator "is unbiased but only allows for one step of optimization per round of data collection" — [Black et al., Training Diffusion Models with Reinforcement Learning](https://rl-diffusion.github.io/files/paper.pdf)
- DDPO high variance is documented in adjacent domains: for graph diffusion, "high variance of the gradient ∇_θ log p(G_{t−1}|G_t)" causes DDPO to fail beyond 4 nodes, with learning-curve fluctuation growing with problem size; and "scaling DDPO to large prompt sets results in unstable training and subpar performance" — [Graph Diffusion Policy Optimization, arXiv 2402.16302v2](https://arxiv.org/html/2402.16302v2)

### Inferences
- **[THEORY, well-grounded]** The `1/σ_t²` factor is the single mechanistic kernel of this whole cluster. With Flow-GRPO's `σ_t = a·sqrt(t/(1−t))`, as `t → 0` (late/low-noise steps) `σ_t → 0`, so: log-prob magnitudes blow up, the KL penalty blows up, the log-ratio bias `−‖Δμ‖²/(2σ_t²Δt)` blows up, clipping fires constantly, and gradient norms are dominated by exactly the steps where they are least trustworthy. GRPO-Guard measured the ~20× gradient-magnitude spread; λ-Controlled GRPO names the quantity (path variance) and shows it is exactly determined by the transition kernel. This is a published, derived result — not conjecture.
- **[UNSUPPORTED MECHANISM]** A 6-step schedule makes this worse than a 10–40-step schedule for a structural reason: with few steps, each step's `Δt` is large and the per-step `σ_t` grid is coarse, so (a) the Euler-Maruyama Gaussian kernel is a worse approximation of the true transition (the discretization gap LC-GRPO flags), and (b) a larger fraction of the gradient budget lands on the handful of extreme-σ steps, with no neighbouring steps to average over. No source states this for 6 steps specifically.
- **[UNSUPPORTED MECHANISM]** For a guidance-distilled model, `v_θ(x,t,w,c)` is a *fitted* object with its own approximation error, so `∇log p_t` in the ODE→SDE conversion is substituted from a velocity field that is not the score of any explicit density. The resulting Gaussian kernel is thus doubly approximate (discretization + distillation), which would inflate `Δμ_θ` for a given weight change and hence inflate the `‖Δμ_θ‖²/(2σ_t²Δt)` bias term. This is a coherent reading of GRPO-Guard's equation applied to a distilled model, but nobody writes it down.

### Gaps
- No paper isolates guidance distillation (vs. architecture, vs. model size, vs. schedule) as the cause of FLUX.1-dev's extra fragility. V-GRPO establishes FLUX.1-dev is less robust than SD3.5-M but does not attribute it.
- The "Flow-GRPO fails on FLUX.2 because guidance is embedded" claim is unverified (see above).
- No published per-timestep importance-ratio statistics at 6 steps.

## Q4. How many denoising steps should receive gradient, and does restricting to high-σ vs low-σ steps change what can be learned?

### Takeaway
There is a substantial 2025–2026 literature on exactly this, and the consensus is that (a) gradient need only reach a subset of steps, (b) the *choice* of subset matters and should move over training, and (c) early high-noise steps govern global layout/composition while late low-noise steps govern fine detail and texture. The specific claim that late steps control rendered text glyphs is the weakest link: the best evidence says *mid* steps are most informative for text placement, not late steps.

### Cited Findings
- **[MEASURED]** Flow-GRPO's Denoising Reduction: `T = 10` steps for training rollouts, `T = 40` at inference for SD3.5-M. "Reducing data collection timesteps from 40 to 10 achieves over a 4× speedup across all three tasks, without impacting final reward. Further reducing to 5 does not consistently improve speed and sometimes slows training, so we choose 10 timesteps." They also state as a headline finding: "online RL for flow matching models does not require the standard long timesteps" — [Flow-GRPO §4, §5.3](https://arxiv.org/pdf/2505.05470)
- **[MEASURED]** MixGRPO confines SDE sampling and GRPO optimization to a sub-interval of timesteps, following a deterministic ODE outside the window, shortening the effective MDP horizon. The window *slides*: "Early in training, the window focuses on initial timesteps to allow exploration of global layout and composition, then in mid-to-late training the window slides toward later steps for optimizing fine-grained details, textures, and aesthetic refinements." Controlled by window size `w`, shift interval `τ`, and stride `s`; reports ~50% lower training time than DanceGRPO — [MixGRPO, arXiv 2507.21802](https://arxiv.org/pdf/2507.21802) (mechanism description from the search synthesis of the paper; the sliding-window parameterization is the paper's core contribution)
- **[MEASURED]** V-GRPO finds a saturation effect in how many timestep samples get gradient: reducing `N_MC` from 4 to 2 "prevents convergence, while increasing it to 8 yields only marginal gains. This mirrors findings in MDP-based methods regarding the 'number of timesteps optimized', suggesting a consistent saturation effect across both paradigms" — [V-GRPO §5.4, Fig. 4f](https://arxiv.org/pdf/2604.23380)
- **[MEASURED]** V-GRPO's *stratified timestep sampling*: "Standard uniform timestep sampling can cause different outputs to draw from distinct regions of the noise schedule, leading to imbalanced optimization dynamics. To ensure representative and consistent coverage across the entire schedule for every output, we replace uniform sampling with a stratified scheme" — partitioning the schedule into `N_MC` disjoint equal-length intervals and drawing one `t` from each. Removing this "destabilizes training" on FLUX.1-dev — [V-GRPO §4.4, §5.4](https://arxiv.org/pdf/2604.23380)
- **[MEASURED]** V-GRPO's *group-shared timestep-noise pairs*: for a prompt `c`, one fixed set `{(t_j, ε_j)}` is reused across all `G` outputs, "anchoring all outputs to the same stochastic basis… eliminates a major source of intra-group variance and renders the resulting policy gradient contributions directly comparable" — [V-GRPO §4.4](https://arxiv.org/pdf/2604.23380). **This is directly a seed-variance reduction technique and should be highlighted.**
- Prior differentiable-reward practice restricted gradient to *late* steps: ImageReward-style fine-tuning "back-propagat[es] gradients to a randomly chosen late timestep t ∈ [30, 40]" out of 40 — described in Flow-GRPO's appendix as the baseline method — [Flow-GRPO Appendix](https://arxiv.org/pdf/2505.05470)
- GRPO-Guard's gradient reweighting exists precisely to stop "excessive updates concentrated in particular timestep regions" — [GRPO-Guard](https://arxiv.org/html/2510.22319v1)
- λ-Controlled GRPO "allocates gradient effort across denoising steps according to their predicted cost" and reports that it "keeps late-step path variance within its intended budget, precisely where the baseline systematically overshoots" — [λ-Controlled GRPO](https://arxiv.org/abs/2609.22041). **So late (low-σ) steps are where the published diagnosis says the variance budget is blown.**
- TempFlow-GRPO is built on the premise that timing matters: it reports ~0.3 performance gain over Flow-GRPO on FLUX.1-dev after 300 steps and reaches comparable performance in 80 steps (3.75× convergence speedup) — [TempFlow-GRPO, arXiv 2508.04324](https://arxiv.org/pdf/2508.04324) (numbers from search summary; I could not fetch the PDF, it exceeded the fetch size limit, so these figures are second-hand)
- Which steps control what — general: early/high-noise steps set "the overall scene layout… placing people and major objects in roughly the right spots, and choosing the general colors and lighting mood"; final/low-noise steps "add the finishing touches, sharpening edges, adding fine details…" In SD-style UNets, early steps are "dominated by the deep, low-resolution features, with cross-attention at 8×8 determining where subjects go", late steps "increasingly influenced by the high-resolution features, with cross-attention at 32×32 determining what textures appear" — [Diffusion Models II: Inside Stable Diffusion](https://januverma.substack.com/p/diffusion-models-ii-inside-stable); [Diffusion Explainer](https://poloclub.github.io/diffusion-explainer/) (both are explainer-quality sources, not peer-reviewed measurements)
- Which steps control **text glyphs specifically**: "mid steps are most informative for writing placement, while early steps are coarse and reflect global planning, and late steps become diffuse due to global refinement"; and at the frequency level "high-frequency structures determine texture clarity, edge sharpness, and text readability" — [FreeText: Training-Free Text Rendering in Diffusion Transformers via Attention Localization and Spectral Glyph Injection, arXiv 2601.00535](https://arxiv.org/html/2601.00535) (search summary; this is the most on-point source for the glyph question and it says **mid**, not late)

### Inferences
- **[UNSUPPORTED MECHANISM, but well-aligned with sources]** Restricting gradient to the earliest high-σ steps buys you numerical safety (large `σ_t`, small `1/σ_t²`, ratios near 1, clipping rarely fires — per GRPO-Guard) at the cost of losing the levers that control fine detail. For a global-composition reward (GenEval-style) this trade is favourable; for a glyph-accuracy reward (OCR) it is likely *unfavourable*, because the evidence points at mid-to-late steps as the ones carrying writing placement and high-frequency legibility. MixGRPO's sliding window is the published reconciliation: start high-σ, slide toward low-σ.
- **[UNSUPPORTED MECHANISM]** With only 6 steps there is no clean separation between "high-σ structural" and "low-σ detail" steps — a 6-step schedule compresses the whole σ range into six coarse bins, so a window restricted to the top 1–2 steps may exclude every step that can affect glyphs. This is a direct prediction of the above, not a published finding.

### Gaps
- I found no study that measures reward attainable per-task as a function of *which* σ-band receives gradient, holding everything else fixed. MixGRPO's ablation is the closest but I only have the search summary of it.
- The "late steps control glyphs" folk claim appears to be wrong or at least imprecise; the one targeted source says mid steps. Worth flagging to the report writer as a correction.

## Q5. Is high seed-to-seed variance a documented property of RL fine-tuning of diffusion models? Quantitative magnitude?

### Takeaway
Instability and high-variance reward curves are extensively documented; *seed-to-seed* variance as an explicitly measured quantity is almost entirely absent from this literature. I found no paper in diffusion RL that reports mean±std across random seeds for its headline numbers, and GRPO-Guard explicitly presents single point estimates with no error bars.

### Cited Findings
- **Negative finding, important:** GRPO-Guard "does not report seed variance, confidence intervals, or run-to-run variability metrics. Results are presented as single point estimates without error bars or multiple-run statistics." Human evaluation uses 100 sample pairs with no significance testing — [GRPO-Guard, arXiv 2510.22319](https://arxiv.org/html/2510.22319v1) (assessment made from fetching the paper)
- **[MEASURED, variance of reward curves rather than across seeds]** DMD+RL: "Figure 10 demonstrates that models trained with only RL show 'significantly greater variance' in reward curves, indicating instability"; RL-alone produces a "rasterized appearance" — a hallmark of reward hacking — [arXiv 2511.13649v2](https://arxiv.org/html/2511.13649v2)
- **[MEASURED]** V-GRPO: naive ELBO-GRPO on FLUX.1-dev "suffers from severe training instability"; "loss spikes" in FLUX.1-dev training are resisted by importance-ratio clipping but not by a KL penalty — [V-GRPO §5.4, Fig. 4b](https://arxiv.org/pdf/2604.23380)
- **[MEASURED]** Graph-DDPO: "as the number of nodes increases, the fluctuation of learning curves grows significantly, implying that DDPO is unable to optimize properly on randomly initialized models" — [arXiv 2402.16302v2](https://arxiv.org/html/2402.16302v2)
- Flow-GRPO's seed observation is about *collapse*, not variance: without KL, "different seeds produc[e] nearly identical results" — i.e. seeds stop mattering for outputs, which is the opposite failure — [Flow-GRPO §5.3](https://arxiv.org/pdf/2505.05470)
- From the general RL (non-diffusion) literature, which is where quantitative seed-variance guidance exists: "Variability between random seeds is a potential source of error when tuning and running RL algorithms"; "the standard deviation of performance for the same hyperparameter configuration can be very large" — [Hyperparameters in Reinforcement Learning and How To Tune Them, arXiv 2306.01324](https://arxiv.org/pdf/2306.01324)
- Caveat on seed-fixing: in fine-tuning studies, "three runs at the same seed can spread as widely as multiple runs at different seeds if the training involves non-deterministic operations, so fixing the seed does not guarantee reproducibility" — [Fine-Tuning Pretrained Language Models: Weight Initializations, Data Orders, and Early Stopping, arXiv 2002.06305](https://arxiv.org/pdf/2002.06305) (reported via search synthesis of that paper's known findings)

### Inferences
- **[UNSUPPORTED MECHANISM]** Because every paper in this space reports a single run, the field has no baseline for what "normal" run-to-run spread looks like in diffusion RL. A practitioner observing large seed-to-seed spread on FLUX.1-dev therefore cannot tell from the literature whether that is anomalous — which is itself a reportable finding.

### Gaps
- **No quantitative report of seed-to-seed variance magnitude for RL fine-tuning of any diffusion or flow model.** This is a genuine hole in the literature, not a search failure — I checked Flow-GRPO, GRPO-Guard, V-GRPO, DMD+RL and found none report it.

## Q6. Is there published guidance on the minimum number of seeds for diffusion RL claims?

### Takeaway
None specific to diffusion RL. The only usable guidance comes from the general RL hyperparameter-tuning literature, and even there the recommendation is nuanced rather than a clean minimum.

### Cited Findings
- General RL practice: "It is common to evaluate a configuration on multiple seeds in order to achieve a more reliable estimate of the true performance." The same source notes a counterintuitive caveat: "performance estimation across more than 3 seeds can lead to a general decrease in test performance, as well as a sharp increase in variance in some cases" (i.e. more tuning seeds can worsen generalization via overfitting of the tuning procedure) — [Hyperparameters in Reinforcement Learning and How To Tune Them, arXiv 2306.01324](https://arxiv.org/pdf/2306.01324)
- General reporting norm: "mean ± spread across multiple seeds should be reported rather than selecting only the best seed" — standard methodological guidance surfaced by search; the concrete citation offered was [Assessing the Macro and Micro Effects of Random Seeds, IJCNLP 2025](https://aclanthology.org/2025.ijcnlp-short.3.pdf), which is an NLP study, not diffusion.

### Inferences
- **[UNSUPPORTED — my own recommendation, not published]** Given the absence of any field norm, a claim about a diffusion-RL method's effect should carry at least 3 seeds with reported spread, and comparisons between methods whose gaps are smaller than the observed spread should be labelled inconclusive. No source endorses a specific number for this domain.

### Gaps
- No diffusion-specific seed-count guidance exists. Report writer should say so plainly rather than importing an LLM/RL number.

## Q7. Are few-step models (≈6 steps) fundamentally harder to RL than many-step models (10–50)? Why?

### Takeaway
Yes, and this is reasonably well supported, though the published analyses are mostly about 1–4-step *timestep-distilled* models (consistency/DMD/ADD-style) rather than a 6-step FLUX schedule. Four distinct mechanisms are named in the literature: limited state space, non-smooth mapping, insufficient intrinsic stochasticity, and absence of a valid regularization reference. There is also direct FLUX evidence that cutting steps from 25 to 16 required extra stabilization.

### Cited Findings
- **[MEASURED/asserted]** "Naively applying uniform-step RL fine-tuning to few-step diffusion models leads to unstable training dynamics and poor sample efficiency"; fine-tuning distilled models with RL "is notoriously unstable and easily falls into reward hacking" — [Flash-DMD, arXiv 2511.20549](https://arxiv.org/pdf/2511.20549); [TDM-R1, arXiv 2603.07700](https://arxiv.org/pdf/2603.07700) (both via search synthesis of the papers)
- Named mechanisms (from the same cluster of few-step RL papers):
  1. **Limited state space** — "Short sampling trajectories in few-step regimes (e.g., 1 to 4 steps) result in limited state spaces and inherently suboptimal output quality, yielding insufficient signal diversity for reliable policy updates."
  2. **Non-smooth mapping** — "The mapping of the distilled 2-step sampler from noisy images to clean ones is highly non-smooth, making policy gradient estimation challenging."
  3. **Lack of stochasticity** — "The 2-step mapping lacks enough stochasticity, posing a hard exploration problem."
  — [search synthesis over arXiv 2511.20549, 2603.07700, 2411.15247](https://arxiv.org/pdf/2411.15247) (these three statements came from the search-engine synthesis; each is attributable to that paper cluster but I did not fetch each PDF to pin each sentence to one paper — the report writer should attribute them to "the few-step RL literature" rather than to a single source)
  4. **No valid regularization reference** — DMD+RL: when RL follows distillation without concurrent DMD, "some modes are inevitably neglected after being distilled, thus P_fake-ref cannot serve as an effective regular[izer]". Their fix: "DMD loss continuously pulls the student generator's distribution towards the multi-step teacher's distribution" — [arXiv 2511.13649v2](https://arxiv.org/html/2511.13649v2)
- Mitigations in the literature, which indirectly confirm the diagnosis: SDPO's "dual-state trajectory sampling mechanism, tracking both noisy and predicted clean states at each step to provide dense reward feedback and enable low-variance, mixed-step optimization"; dense-reward-difference learning for few-step models — [Aligning Few-Step Diffusion Models with Dense Reward Difference Learning, arXiv 2411.11727](https://arxiv.org/html/2411.11727)
- **[MEASURED, FLUX-specific and directly on point]** V-GRPO needed advantage soft-clipping specifically for "FLUX.1-dev training with sampling steps reduced from 25 to 16" (their Fig. 4d), whereas the 25-step setting was stable with importance-ratio clipping alone — [V-GRPO §5.4](https://arxiv.org/pdf/2604.23380). **This is the single clearest published datapoint that fewer steps = more stabilization needed on FLUX.1-dev.**
- **Counterpoint:** Flow-GRPO found fewer steps *helps* — 10 beats 40 on speed with no reward loss — but also that 5 "does not consistently improve speed and sometimes slows training" — [Flow-GRPO §5.3](https://arxiv.org/pdf/2505.05470). So there is a published non-monotonicity with a turning point somewhere between 10 and 5 steps, which brackets 6.
- A dedicated method exists for the few-step flow-map regime: [Flow-Map GRPO: Reinforcement Learning for Few-Step Flow-Map Generators via Anchored Stochastic Composition, arXiv 2607.00535](https://arxiv.org/html/2607.00535) — its existence implies the standard Flow-GRPO kernel is considered inadequate there.

### Inferences
- **[UNSUPPORTED MECHANISM, assembled from the above]** The 6-step regime sits exactly in the published danger zone: Flow-GRPO's own ablation shows degradation below ~10 steps, V-GRPO needed extra clipping at 16 on FLUX, and the 1–4-step literature documents outright failure. The mechanisms compose: fewer steps → fewer MDP transitions to spread credit over → each transition carries more of the reward and more of the `1/σ_t²` pathology → higher-variance advantage per update → larger run-to-run spread.
- **[UNSUPPORTED MECHANISM]** Note the distinction the report should preserve: FLUX.1-dev is *guidance*-distilled, not *timestep*-distilled (unlike FLUX.1-schnell, LCM, DMD students). Running FLUX.1-dev at 6 steps is schedule truncation of a many-step model, not use of a step-distilled model. The few-step RL literature's "non-smooth mapping" and "no stochasticity" arguments apply to *step-distilled* students and transfer to truncated-schedule FLUX.1-dev only partially — at 6 Euler steps FLUX.1-dev still has a genuine velocity field at every σ and an SDE can still inject noise. The arguments that *do* transfer cleanly are the discretization-error and credit-concentration ones.

### Gaps
- No paper runs the controlled experiment "same model, same reward, same everything, sweep 6/10/25/40 steps, N seeds each, report spread". That is the experiment the brief's question really wants and it does not exist in the literature I found.
- I could not fetch TempFlow-GRPO's or MixGRPO's PDFs (both exceeded the fetch size limit), so their timestep-allocation ablations are reported here only via search summaries.

## Summary for the report writer: what is established vs. what is conjecture

**Established and measured (safe to assert):**
1. FLUX.1-dev takes guidance as a conditioning embedding scaled by 1000 and added to the timestep embedding; no unconditional pass exists. (model card, BFL discussion, diffusers source)
2. The flow-GRPO Gaussian log-ratio has an exact `−‖Δμ_θ‖²/(2σ_t²Δt)` bias; ratios drift below 1; variance and gradient magnitude differ across timesteps by ~20×, dominated by low-σ steps. (GRPO-Guard; λ-Controlled GRPO)
3. FLUX.1-dev is empirically less robust to likelihood-surrogate RL than SD3.5-M and requires variance-reduction machinery (group-shared timestep-noise pairs, stratified timestep sampling) that SD3.5-M does not. (V-GRPO)
4. Reducing FLUX.1-dev's sampling steps from 25 to 16 required additional advantage soft-clipping for stability. (V-GRPO)
5. Flow-GRPO trains at 10 steps and infers at 40; dropping to 5 is counterproductive. (Flow-GRPO)
6. RL on step-distilled few-step models is unstable for named reasons: limited state space, non-smooth mapping, insufficient stochasticity, no valid reference distribution. (few-step RL cluster; DMD+RL)
7. Which-steps-do-what: early/high-σ → layout and composition; late/low-σ → detail and texture; **mid** steps → text placement. MixGRPO's sliding window operationalizes this.
8. CFG reduces diversity with increasing scale, and CFG-distilled students lose diversity relative to their CFG-free initialization (qualitatively/human-eval measured, not quantified).
9. GRPO advantage collapses when within-group reward variance vanishes.

**Conjecture (label clearly as unsupported):**
- That guidance distillation specifically — as opposed to architecture or scale — is what makes FLUX.1-dev fragile under RL.
- That reduced output entropy from guidance distillation is the proximate cause of high seed variance via small/noisy group advantages.
- That the guidance embedding makes the SDE log-prob kernel additionally miscalibrated because `v_θ(·,w)` is not the score of any explicit density.
- That 6 steps is specifically where the regime breaks for FLUX.1-dev.

**Genuine holes in the literature:**
- No measured output-entropy comparison of FLUX.1-dev vs de-distilled/CFG equivalent.
- No seed-to-seed variance numbers anywhere in diffusion RL; GRPO-Guard and others report single runs with no error bars.
- No diffusion-specific minimum-seed guidance.
- No controlled step-count × seed sweep.
- Unverified claim needing re-sourcing: "Flow-GRPO fails on FLUX.2 because likelihood estimation becomes inaccurate when the guidance scale is embedded in the DiT."
